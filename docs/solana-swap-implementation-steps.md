# Solana swap implementation steps

**Status: step 1 complete; step 2 pending.** This checklist preserves the agreed build order. The [system design](solana-swap-system-design.md) specifies the trust boundary and wallet flow. No Zebra source changes are planned.

1. **CATE script proof. Complete on 2026-11-26.** The external [HTLC harness](../proofs/cate-htlc/README.md) verifies both script branches and negative cases against unchanged Zebra code. The offline verifier test passed. On live devnet, two 0.01 CATE locks were funded from confirmed ordinary outputs, then a maker claim and a taker refund after the lock height both confirmed. Rebroadcasting either spend was rejected. A fresh client process and a restarted local Zebra container both read the same confirmed spends from the saved recovery record. The harness writes that record atomically, reconciles already-broadcast transactions, and reports spend confirmations. This proves the isolated script path, not a cross-chain swap or audited wallet integration.
2. **Solana program.** Build and review the on-chain funded USDC bid book and escrow with signed acceptance, fixed recipient, secret claim, cancellation, and timed refund. Pending.
3. **Cross-chain integration.** Connect local CATE signing and Solana clients, then test full trades and both refund outcomes. Pending.
4. **Chrome wallet UI.** Add Trade, review, progress, and recovery, plus companion Solana wallet signing. Pending.
5. **Test service.** Run the companion UI and read-only indexer in containers at `swap-test.catecash.com`; keep settlement authority on-chain. Pending.
6. **Public release gates.** Audit, test outages/reorganizations, set measured deadlines, and complete Catecash network and Solana program launch checks. Pending.

The local test uses the existing `catecash-local-devnet` container and loopback cookie-authenticated RPC. No Zebra files were edited. An attempt to preview a staging-wallet transfer through the **external** devnet indexer was rejected by automatic approval review because it would disclose wallet-derived addresses and activity to that service; it was not run. A local-only funding path or explicit approval for that disclosure is needed before the live proof can finish.

On 2026-11-26, the hosted devnet miner's live payout configuration was checked over SSH: it pays `yPgDzCsVBJ5g5S9Y72uAZK2WBbwwXvLQoQp`. The local devnet node's configured payout is `yPk8KYMRrKnumaQALZ4rPkbJjCMfGkVXjGN`. No transfer was sent. A second automatic review rejected an external-indexer preview even after the user authorized using a devnet wallet, because that authorization did not specifically cover disclosing wallet-derived addresses and activity to `wallet-devnet.catecash.com`.

The local Chrome wallet engine had previously **prepared** a coinbase-to-Ironwood transaction from the controlled devnet miner key using only loopback RPC. A coinbase input is indivisible: that proposed transaction moved the full 5,000 CATE reward into a temporary shielded account. Automatic approval review rejected broadcasting it because the requested test transfer was only 0.1 CATE total. Nothing was broadcast then, and that temporary seed record was removed.
